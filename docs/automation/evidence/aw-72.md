# AW-72 — extension: disconnect removes the account's automation data and keeps browser rules

Built on AW-71 (`d0d7a229`) on `main`. Design [01 §7.5](../design/01-architecture.md#75-browser-rules-adr-a24-au-34),
stories AU-34 and AU-33 (point 3); acceptance AC-74.

## What shipped

### One cleanup on sign-out (`src/sw/auth.ts`)

The `known.auth.logout` handler already cleaned subscriptions and the Sync state once sign-out succeeded. It now
also calls `clearAccountAutomation` for the account that signed out. *Disconnect server* goes through the same
handler (`src/sw/server-disconnect.ts`), so both paths clean up. A failure here never fails the sign-out.

### What goes (`src/automation/indexeddb-store.ts`, `src/sw/automation.ts`)

`clearAccount(ownerKey)` removes, in one IndexedDB transaction:

- the bundle record, when it is that account's;
- the server-status copy, when it is that account's;
- that account's receipts, keeping the rest of the list;
- that account's placement intents.

It then bumps the change marker so open pages re-render. `clearAccountAutomation` also removes from
`chrome.storage.local`:

- the pause details and the cached device id, when they are that account's;
- the toolbar count, by repainting the digest badge with no account.

Another account's receipts and intents keep waiting for it, as recovery already expects.

A refresh pass can still be running at sign-out (for example, waiting for the bundle). It may write after the
cleanup. So the cleanup runs again once that pass ends. It does not wait on the pass: the logout handler runs
in the auth lane, and the pass may need that lane.

### What stays

`known.automation.browserRules.v1` and `known.automation.browserPlacements.v1` are never touched. Browser rules
keep placing saves with no account (AW-67), and Options keeps their recent activity.

**`automation-disconnect.test.ts`** (4 tests) runs the real `handle({ kind: 'known.auth.logout' })`. Mocked:
`runtime`, `scope`, the device client and the subscription and Sync cleanups. Real: fake-indexeddb and an
in-memory `chrome.storage.local`.

- Before sign-out, the account's rule decides the page. Afterwards these are all gone: the bundle, the status,
  the account's receipts and intents, and the pause, device and badge keys. Another account's receipt and intent
  remain.
- The browser rules and their log are byte-for-byte unchanged. With the capture scope still naming the account,
  the popup preview and `browserPreSaveDecision` now place the page by the browser rule (AC-74).
- A manual refresh is held at the bundle fetch, sign-out runs, then the bundle arrives. The bundle is gone
  again once the pass ends. With the second cleanup removed, this test fails.
- `clearAccount` for an account with no data changes nothing.

## Limitations

- Only sign-out cleans up. Signing in as another account without signing out first leaves the earlier
  account's data. That data is never used for the new account (every record is checked against its owner),
  and settled receipts age out.
- Receipts not yet sent when the Owner signs out are dropped (AU-33). The server never hears about those
  placements.
- *Disconnect server* in Options still says only "Bookmarks on this browser are kept." It does not mention
  browser rules.
