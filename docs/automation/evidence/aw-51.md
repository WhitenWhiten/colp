# AW-51 — verified placement history and conservative Undo

Parent commit 4167980. A verified device placement now records a separate effect receipt pinning the canonical operation,
the before/after resource revisions, the original folder (when provable), the content revision at commit and the effect digest.
getAutomationRun returns bounded effects with a dynamic undoAvailable/reason; no Agent/target/policy.
Adds undoAutomationRun through the existing Owner cookie/CSRF/command/If-Match entry; a single transaction re-locks
the current Owner collection, checks the resource/content/destination fences, executes one compensating canonical
move and marks the receipt reverted. It never deletes the create and never performs a whole-collection snapshot restore.

Actual verification: typecheck, check:imports, ESLint, git diff --check and openapi:ci passed.
Real PostgreSQL placement-undo.integration.test.ts passed three cases:
1. without original-folder evidence from pre-save, it explains that Undo is unavailable;
2. a single create→move effect can be compensated, an HTTP command replay produces only one undo operation, and the bookmark content remains;
3. a later manual Owner move makes the old Undo return conflict, keeping the new location.
No browser or model calls; test containers were reclaimed. Hooking server-intake into this effect/Undo mechanism was done in AW-33.
