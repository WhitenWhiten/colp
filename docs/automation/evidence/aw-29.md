# AW-29 — durable ready-job wake delivery

Ready transitions atomically insert a reference-only occurrence for each currently
eligible subscription; job/recipient identity is unique. Poll targets create none.
The target/executor snapshot remains the existing admission-time pin. Setup and
reconnect must list the durable queue; no historical occurrence replay is invented.

A bounded worker loop leases one occurrence at a time, signs its stored body/id on
each attempt and sends outside locks. Account-first locking, generation checks,
current credential/target/source-owner checks and pause fencing apply before send
and completion. Expired delivery leases can retry, without authorizing a second
job claim. Eight automatic attempts, capped jitter/backoff and Retry-After apply.
410 revokes the subscription path; 413 dead-letters only that occurrence. Terminal
failures create persistent health incidents. Target revocation or switching to poll
cancels pending/sending records. Secrets are not returned by Owner delivery APIs.

Owner list/retry routes, generated backend OpenAPI and active-subscription readiness
are installed. The worker timer is stopped and in-flight ticks awaited on shutdown.
Migration 202610301900 follows AW-27's 202610301800.
