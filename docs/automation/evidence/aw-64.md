# AW-64 — authenticated loopback polling and recovery gate

Baseline `e334e34`, branch `feat/colp-automation`, schema `0.2.1-design` plus the
committed additive producer adjustments. The gate uses PostgreSQL 16.4, actual
account-key exchange/credential epochs, existing Owner configuration/approval,
real loopback HTTP and the AW-32 reference worker with deterministic typed output.
The `.integration.test.ts` suffix follows the repository's PostgreSQL discovery
pattern rather than the proposed task's `.test.ts` filename.

## Executed scenarios

1. M1 device receipt arrives before canonical Sync. The authenticated device HTTP
   endpoint waits, joins the real Sync operation, accepts once, and preserves the
   original command response on replay. Reinspection leaves one run and no
   fabricated optional worker jobs/plans.
2. Worker-only bootstrap over HTTP conceals the unpaired queue, then the actual
   reference redeems the grant and lists work. The server-intake summary-only
   fixture creates one job. A separate worker process reads inputs and commits one
   sourced, attributed note through one plan. Repeated list/inspection does not
   create another run or optional effect.
3. The three-task fixture runs refine → tags → summary with an injected adapter.
   The summary consumes the accepted typed tags predecessor. Exactly three jobs,
   three plans, three optional effects, canonical resource revisions and linked
   pre-commit versions persist. Node facts retain automation root/stage lineage;
   canonical operations remain linked by their real commit ordinals. Reinspection
   does not re-intake. Later effects make the earlier placement Undo unavailable;
   the authenticated Undo command rejects compensation that would discard them.
4. A real backend process is SIGKILLed immediately before canonical commit. A new
   backend and worker process resume the persisted submission with the same input,
   plan and original command, without another provider invocation.
5. The backend is SIGKILLed after canonical commit and before the automation effect
   receipt/HTTP acknowledgment. The committed note exists while the job receipt
   does not. Restart links the same consumed plan/version/operation into one effect.
   Exact and fresh-HTTP-command repeats return the same accepted effect identity;
   only one attempt and one note remain.
6. A worker process is SIGKILLed inside an external adapter call. Restart reports
   unknownOutcome without repeating the adapter. An explicit Owner retry retains
   the original input digest, increments generation, and preserves both unknown
   cost observations while reserving that run only once.
7. The reference retains a Manual proposal across Owner approval and resumes it in
   a new process without calling the provider again. Repeated claim commands cannot
   reissue the one-time lease; heartbeat replay is stable and a foreign generation
   is rejected. Revoking the real credential prevents later reads/submissions.
8. A later manual source edit rejects the original typed output before any optional
   plan/note/effect, preserving the user's title and prior deterministic effect.

AW-64 exposed and fixed an AW-32 recovery gap: acknowledged awaitingApproval or
committing responses now retain the proposal. A later poll uses a fresh HTTP
command with the same typed body so immutable pending HTTP receipts do not prevent
plan reconciliation. Lost responses still replay their original command. The
serial reference waits for that proposal before claiming another job, preventing
journal overwrite. A focused transport test covers this distinction too.

## Acceptance boundary and AW-35 handoff

This is local backend evidence, without Events, a provider key or frontend.
Browser bundles currently support the finite M1 profile, so M1 receipt/Sync and M2
polling fixtures are proved separately; this gate does not assert an M2 browser
bundle or real browser lifecycle. The injected three-task adapter is a transport
fixture; the shipped example supports sourced summary only. The test server uses
actual runtime services/transport/credential verification, with crash hooks only
in test composition; this is not a full deployed-server startup test. All test
children, HTTP listeners, temporary journals and PostgreSQL containers are cleaned
up by the fixture/wrapper. See the [release handoff](../release-evidence.md).
