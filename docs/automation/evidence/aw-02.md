OpenAI dot subscribing to `colp.automation.triggered`, accepting a signed webhook,
and calling the fixture's acknowledgment tool with the delivered identifiers.

## Compatibility findings for AW-27

1. **Preserve the Events capability explicitly.** SDK `2.3.1` emits
   `capabilities.events` on the server's wire response, but its public
   `DiscoverResultSchema` and client discovery parsing strip that field.
   Custom `events/*` calls work with explicit schemas. The production boundary
   still needs an approved Events schema extension and round-trip regression
   coverage; the fixture did not change COLP's SDK allowlist.
2. **Advertise delivery mode.** The first descriptor omitted
   `delivery: ["webhook"]`. ChatGPT scanned it but the dot could not discover it
   as an event source. Adding the field and refreshing the plugin resolved this.
   [Wire catalog](fixtures/aw-02/wire-catalog.json) preserves the corrected shape.
3. **Use the cloud plugin's authentication path.** This account's web UI offered
   OAuth or no authentication. The fixture implemented DCR, S256 PKCE and token
   refresh. A browser-only failure required changing the authorization page's
   referrer policy and allowing the validated ChatGPT redirect in CSP. Local
   and public Chromium checks ran under `xvfb-run`; browsers were closed.
4. **Test real egress, not only an injected receiver.** Node 24 requests
   `lookup(..., {all: true})` for automatic address-family selection. Returning
   a scalar caused `ERR_INVALID_IP_ADDRESS` and two real subscription failures.
   Returning an array in that mode fixed the pinned-address HTTPS transport.
   Private-address checks, TLS hostname verification and redirect blocking were
   retained. The corrected deployed transport made a real public HTTPS POST.
5. **Keep protocol errors distinct.** Failed verification returned OpenAI's
   `-32015`, followed by platform cleanup via `events/unsubscribe`. Those cleanup
   calls do not prove cancellation of a successfully running subscription.
6. **Receipt is not execution.** Correlate event/job identifiers with subsequent
   tool calls. Do not infer a committed COLP effect from a webhook 2xx or from
   the fixture's acknowledgment.

## Remaining gates and operational state

- AW-27/AW-28/AW-29 still own production adapter, lifecycle and delivery work.
  This fixture used the SDK codec, not COLP's complete production request,
  authorization or egress adapters.
- All OAuth clients share one pre-paired fixture principal. Neither dedicated
  per-dot credentials nor two-target isolation was demonstrated. The design's
  G3 isolation gate remains open.
- G1's feasibility question is answered, but its no-schema-stripping production
  condition is not: the SDK limitation above must be addressed in AW-27.
- AW-46 still needs successful-subscription cancellation, hosted expiry/refresh,
  bad-signature behavior, duplicate/out-of-order delivery, batching, revocation
  and production job/effect evidence. Local tests are not hosted proof of these.
- The fixture has no production job ledger, durable delivery queue, concurrent
  refresh fencing or real bookmark mutation. Retry-After scheduling is absent.
- The service was deliberately retained for the user's ongoing remote test.
  The observed subscription deadline was `2026-10-13T04:32:55.566Z`; future
  activity must recheck status rather than assume it is still active. No local
  development server was left running. To stop the fixture, use
  `ssh s2 'docker stop colp-aw02'`; cancel monitoring in the dot separately.
