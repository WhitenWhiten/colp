# AW-23 — fenced claims, heartbeat and uncertainty

Baseline `eabf2c8`, design `0.2.1-design`. Adds the job pins/lease migration `202610301100` (renamed `202610301150_automation_job_leases`
after review to restore unique G9 prefixes). A short transaction locks the current active Account, the Owner collection and the uncancelled, unheld run/job;
TargetAuthority is a required current-authority port, and AW-26/31 mount the real pairing authority and transport.
Claims default to 120 seconds, the token is stored only as SHA-256, and generation is monotonic; heartbeat renews by at most 120 seconds,
and the reference worker calls it every 30 seconds. The token does not replace authentication; a wrong credential binding, an old generation,
losing the Owner, a revoked account, hold or pause all prevent completion. The HTTP 503/Retry-After of list/claim
is mounted together in AW-31, and the current application errors register automation_paused=503 centrally.

knownRetryable allows the next generation (still bounded by maxCalls/caps); permanent fails;
unknownOutcome and expired leases durably become uncertain and are not retried automatically. The expiry transition commits first and then
returns the conflict, so an exception rollback cannot lose the uncertainty. The external-call permit is accounted at claim and cannot be treated as model
success or a known cost; later read models must keep this meaning.
