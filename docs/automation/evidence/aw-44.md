# AW-44 — retention, restore and bounded-load evidence

The restore script runs protection SQL before restarting services: all accounts are
paused, configuration epochs advance, leased external attempts become unknownOutcome
and their jobs uncertain. Existing proposals/plans keep their identities for later
reconciliation. Active subscriptions lose secret material and require revalidation;
pending/in-flight wakes are cancelled with a restore diagnostic. Resume alone cannot
produce a redelivery storm. The SQL is safe to repeat and checks table availability
for older backup generations.

The worker performs bounded per-owner maintenance. Expired preview/pairing records
are removed; expired subscriptions/rotation keys lose secrets. Wakes expire after
seven days into terminal records with incidents. Unfinished source membership, job
inputs, result/effect history and dedup identities are conservatively retained;
this implementation does not silently apply a generic deletion horizon to them.
No larger capacity defaults are introduced.

Executed with Node 22/PostgreSQL/xvfb:

  suite 43.26s, tests 37.95s. Includes actual pg_dump/pg_restore followed by deployment

- Node evaluator-load + validation-budget suites: 11 passed, 3.60s total. The load

## Device snapshot follow-up (2026-10-16 UTC)

Unchanged device polls now return the existing immutable bundle for up to one day,
with renewal whenever less than one day remains before expiry. Every poll still
rechecks live collection authority, synced replicas, bindings and rule compilation;
changed content, configuration epochs, pauses and rejected bundles require a new
revision. Reuse preserves the original digest and expiry rather than extending an
already issued evidence record. Stable five-minute polling therefore creates about
365 snapshots per device/year instead of 105,120, excluding configuration changes
and rejected snapshots.

M1 maintenance deletes at most 500 snapshots per owner/pass that expired more than
30 days ago. All snapshots referenced by any intake receipt are retained, as is
the latest revision for each device, including dormant devices. The latter keeps
future issuance monotonic after cleanup. Referenced evidence can still grow with
actual activity; this cleanup does not impose an audit-history deletion policy.
Migration `202610311000_automation_bundle_retention` indexes owner/expiry scans and
receipt bundle references.

Real PostgreSQL regressions cover 20 unchanged polls producing one row, renewal,
live folder loss/recovery without an epoch change, bounded multi-pass deletion,
receipt evidence, recent snapshots, owner isolation and post-cleanup issuance.
The two new cases, four authenticated bundle cases and four existing Events/M1
maintenance cases passed under xvfb. The extension's eight bundle-store cases also
passed, including unchanged installs. Server typecheck, changed-file lint, import
boundaries and migration order passed.
