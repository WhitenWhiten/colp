# AW-44 — retention, restore and bounded-load evidence

The restore script runs protection SQL before restarting services: all accounts are
paused, configuration epochs advance, leased external attempts become unknownOutcome
and their jobs uncertain. Existing proposals/plans keep their identities for later
reconciliation. Active subscriptions lose secret material and require revalidation;
pending/in-flight wakes are cancelled with a restore diagnostic. Resume alone cannot
produce a redelivery storm. The SQL is safe to repeat and checks table availability
for older backup generations.

The worker performs bounded per-owner maintenance. Expired preview/pairing records
are removed; expired subscriptions/rotation keys lose secrets. Wakes expire after
seven days into terminal records with incidents. Unfinished source membership, job
inputs, result/effect history and dedup identities are conservatively retained;
this implementation does not silently apply a generic deletion horizon to them.
No larger capacity defaults are introduced.

Executed with Node 22/PostgreSQL/xvfb:
- `events-retention.integration.test.ts` + `persistence.integration.test.ts`: 8 passed,
  suite 43.26s, tests 37.95s. Includes actual pg_dump/pg_restore followed by deployment
  SQL, pending external attempt recovery, repeated restore, zero post-restore sends,
  terminal wake retention with unchanged job pins, and 25 canonical new bookmarks
  accumulating 26 ready jobs behind an intentionally idle worker while Owner reads
  remain available.
- Node evaluator-load + validation-budget suites: 11 passed, 3.60s total. The load
  case compiles 500 rules and executes 500,000 evaluations over 1,000 fact selections,
  asserting every decision. A measurement-only rerun reported 2.89s test execution
  (3.08s suite). These local timings are observations, not production latency SLAs.
- Server typecheck passed.
