# AW-41 — immutable run-once preview/start

Owner API now persists an expiring snapshot of selection options, rule/binding/policy
and authority digests, exact member facts and revisions. Preview is effect-free;
selection reads at most 1,001 identities, retains at most 1,000 and refuses start if
there is an extra member. Start requires previewId + digest, validates current Owner,
configuration, pause and canonical revisions, then executes exactly the stored set.
It never silently reselects newer nodes or schedules recurring/backfill work.

A manual parent records the selected set; additive Run.childRunIds exposes one child
per matched member. Each child owns its original placement/task/effect/Undo identity,
so multi-member work reuses the proven single-source DAG and effect gateway. Parent
read status derives from its children and parent cancellation cancels pending children.
Default options preserve non-root placements; only the explicitly previewed option
permits moving already-foldered bookmarks. tasks=none starts no worker jobs.

The whole start, canonical placements, child runs/jobs and preview consumption share
the Owner transaction. Duplicate commands replay, and a new command referencing an
already consumed preview returns that same manual parent. Migration 202610302000
adds immutable preview data after AW-29's 202610301900. Backend contracts/package and
OpenAPI artifacts are regenerated; no frontend runtime changes.

[Consumer fixtures](fixtures/aw-41/handoff.json) include preview/over-limit, stale,
denied and started semantics. IDs are synthetic; the executable integration suite
validates actual Preview and Run DTOs.
