# AW-24 — typed proposals and the existing Plan coordinator

Baseline `4bfd189`; design `0.2.1-design`. `202610301200` adds durable proposals and version linkage.
The closed input schema, task/output contract and pinned source evidence are validated before entering the job lock.
Then the current Owner/target, generation/token, input digest/resource revision and live folders are checked.
The model can only submit typed output; the service builds a single reversible move, a tags union or an attributed note create/update,
and rejects out-of-bounds placement. Typed outputs without a canonical effect, such as metadata/review/digest, get no fabricated plan.

First a transaction saves the proposal/result, a stable plan ID, command ID, canonical operation ID and committing;
then, outside the transaction, the existing COLP change-plan service and production coordinator are called; finally a short transaction links
the canonical operation, pre-commit version, effect receipt and accepted job. An unknown commit result keeps
committing; recovery finds the same plan and does not re-plan. Manual uses the existing Approvals, and Trusted reuses
the existing agent policy, version, approval, digest/revision/scope/rate-limit paths.

Host-private registered operations extend the existing executor; the frozen COLP generic changes.plan
operation enum is not widened. The permission required is the actual automation:work; no nodes:write/manager
permission is invented for workers. The production coordinator's beforeBeginCommit accepts the same current job authority guard (mounted in AW-31).
The annotation ports were extracted from the existing adapter to join the existing coordinator's transaction; the original annotation UoW
keeps its receipt/canonical invariant guards. An existing note has content and attribution appended, without replacing user text.

Fixed the same real crash window: when Trusted had already captured the version first, the commit hook must still write the
version receipt inside the commit transaction and must not skip it because a prior snapshot was found, so a process crash after commit
but before the helper saves the receipt cannot lose the history link.

This is a standalone service gate: real PostgreSQL/canonical/Plan/Approval/version, with M2 job pins built by an explicit
service fixture; it is not yet end-to-end proof through authenticated worker transport/admission; AW-31/64 close that loop.
No model calls, no Events/Web/native. The existing tree snapshot does not cover tags/notes, so AW-25 must
state these single-effect Undos are unavailable and cannot claim field restore. Test services were all reclaimed.
