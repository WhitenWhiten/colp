Built on AW-20 (`06c3ba9`) on `main`. Contract `0.2.1-design`, profile `browser-bounded-v1`, shared core
`@know-n/colp` 0.2.0, M1 rule fixture
([m1-placement.json](../../../packages/extension/tests/fixtures/automation/m1-placement.json)). Story AU-10;
acceptance AC-10.

## What shipped

### One IndexedDB store (`src/automation/indexeddb-store.ts`)

The installed rule bundle, the placement receipts and the write-ahead intents of observed moves now
live in one IndexedDB database, `known-automation` (version 1):

| Object store | Holds | Key |
| --- | --- | --- |
| `state` | the bundle record (`known.automation.bundle.v1`) and the receipt list (`known.automation.receipts.v1`), in the shapes AW-49 and AW-50 already read and write | the same key names |
| `intents` | one record per observed move about to happen | `intentId` |

- **Writes are atomic.** Every write is one transaction, and the database outlives worker restarts
  and browser restarts.
- **Migration.** Earlier builds kept the bundle and receipts in `chrome.storage.local`. They move
  into IndexedDB once, the first time the worker opens the store, and are then removed there.
  - A value already in IndexedDB is never overwritten by an older copy.
  - A failed move does not block the store. It is retried on the next open, and the old values stay
    where they were until then.
- **Change marker for pages.** IndexedDB has no change events. Each write sets
  `known.automation.changed.v1` in `chrome.storage.local`, and the Automations pane repaints on that
  key alone.
- **Only the worker opens it.** The store is in the worker bundle only. Options, the popup and Save
  tabs still read automation state through `known.automation.state`.

### Closing the gaps a stopped worker can leave (`src/automation/recovery.ts`)

There are two places where a stopped worker can leave a placement without its receipt. Both are closed
from identity evidence the extension already keeps. Nothing is ever matched by title or URL.

| Gap | Evidence | Recovery |
| --- | --- | --- |
| **Pre-save.** The save was created in the rule's folder, then the worker stopped before the acknowledge hook wrote its receipt. | The capture task, which is durable in the capture store: placed, `local-saved`, new, and saved in the last 7 days. | On worker wake, `wakeCaptures` hands those tasks to `recoverPreSaveReceipts`. That reads the receipt list once and adds only the missing ones. The receipt id is the capture id, so a receipt already written, at any stage, is left as it is. |
| **Observed.** The star-button bookmark was moved (or about to be), then the worker stopped before its receipt. | A write-ahead intent, stored before the move, with the placement's id, native id, `dateAdded`, source and destination folders, and account. | On worker start and on the automation alarm, `resumeObservedCreates` reads the native bookmark. If it has the same id and `dateAdded` and sits in the rule's folder, the move happened, and its receipt is written under the intent's id. Otherwise the intent is dropped, and the move is **never made late**. |

- **Rules for intents.**
  - An intent from another account waits for that account, up to the 7-day receipt lifetime.
  - A completed placement removes its intent right after the receipt is written.
- **Order on the observed path.** `intend` → `move` → `record` → `notify`.

### Synchronization on the existing alarm

- **Bundle refresh backs off.** The refresh still runs on the existing five-minute automation alarm,
  but now only when due.
  - Checks are at least a minute apart.
  - Each failure in a row doubles the gap: offline, signed out, server errors, rate limits and
    rejected bundles all count. The gap is capped at 15 minutes, so a pause still lands soon after
    the server is back.
  - A good install resets the count (`BundleRecord.failures`).
  - A manual check from Options always runs.
- **Generation checks.** Receipts keep AW-50's exponential retry (30 s to 1 h). A receipt from another
  replica or replica generation still needs attention (`staleGeneration`); it is never re-associated.
- **Identity checks.** A receipt whose bookmark was removed before its create ever reached Sync can
  never be joined. After an hour without a create, if the native bookmark is gone, the receipt
  settles as attention (`identityUnknown`) instead of retrying until it expires. The Automations pane
  shows it as "Couldn’t confirm", and AW-54 adds the detailed status.

The tests:

- **`automation-durable-store.test.ts`** (8 tests).
  - The bundle, receipts and intents survive a reopened database.
  - Migration from `chrome.storage.local` happens once and leaves unrelated keys alone.
  - An older copy never overwrites a newer value.
  - The store still opens when the old values cannot be removed, and the move is retried.
  - The change marker is set on writes only.
  - Intent recovery: a move that happened is receipted, and one that did not is never made.
  - A removed, reused or since-moved bookmark is left alone.
  - Another account's intent waits until it expires.
- **`automation-observed-create.test.ts`.** The intent is written before the move, and the receipt
  after it, under the same id.
- **`automation-observed-worker.test.ts`.**
  - The intent is cleared once its receipt exists.
  - On resume, a cut-off move gets its receipt, and an unmoved one gets no move.
- **`automation-worker-pre-save.test.ts` and `capture-pre-save.test.ts`.**
  - On wake, only recent, placed, saved tasks are handed over.
  - A missing receipt is written, and an accepted one is left as it is.
- **`automation-bundle-store.test.ts`.** The backoff steps, the 15-minute cap and the reset on success.
- **`automation-receipt-sync.test.ts`.** The orphaned receipt waits within the hour or while its
  bookmark exists, then needs attention.
- **`e2e/mv3-automation-durable.spec.ts`** (AC-10, real Chromium, xvfb, evidence build).
  1. **Migration.** A bundle written where an earlier build kept it is moved into IndexedDB after a
     worker kill (CDP `Target.closeTarget`). The `chrome.storage.local` copy is gone.
  2. **Filing.** A page starred into the Bookmarks bar is filed by the migrated rules, with one
     `observed` receipt and no leftover intent.
  3. **A cut-off move.** Two intents are written as a worker would before its moves: one whose move
     reached the bookmark tree, one whose move never happened. After another worker kill, the
     automation alarm receipts the first under its intent id and leaves the second bookmark in the
     bar.
  4. **Browser restart** with the same profile. The bundle and the receipt list are byte-for-byte
     unchanged, the filed page is still in Academic, and Sync holds exactly one `create` and one
     `move` for it. Nothing changes over a further settle window.

## Limitations

- **The server half of AC-10 was not run.** "The server joins the receipt to the sync operation" needs
  a live server. The join itself is AW-50's, tested against the server's own digests, and the receipts
  that survive here are the same documents. "No second run" is shown on the browser side only: one
  move, one receipt per placement, and stable receipt ids across restarts.
- **The e2e restores its scope by hand.** It restores its pinned Sync scope with
  `recoverBookmarkEventEvidence` after each restart. In production the scope comes from stored
  credentials and is available when the worker starts.
- **The e2e triggers the alarm itself.** It fires the automation alarm by recreating it from the
  page, instead of waiting five minutes.
- **The bundle refresh is skipped there.** The evidence build has no signed-in account, so the refresh
  is not exercised in the browser; the unit tests cover it.
- **A cut-off move is never finished.** If the worker stopped between writing the intent and the move,
  the bookmark stays where the Owner left it, with no move and no notice. If it stopped after the move
  but before the notice, the receipt is written and the notice is not shown again.
- **Observations still live in session storage.** A star made just before a browser restart is not
  judged after it (AW-20).
- **Receipts are kept for 7 days.** A pre-save save older than that whose receipt was lost is not
  receipted.
- No backend or web files were changed.
