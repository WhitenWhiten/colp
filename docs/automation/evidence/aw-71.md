# AW-71 — extension: move a browser rule to the account

Built on AW-70 (`f4057029`) on `main`. Design [01 §7.5](../design/01-architecture.md#75-browser-rules-adr-a24-au-34),
story AU-34; acceptance AC-73.

## What shipped

### Offered only where it can work (`src/sw/automation.ts`, `src/sw/automation-browser.ts`)

Signed in, each browser rule's folder is looked up in the current Sync scope. Only an authoritative mapping (not
`pending-`, not a `local-` projection, a folder) counts. Then the view carries `move.url`: the web editor filled
in by `accountEditorUrl` (`src/automation/browser-rules.ts`) with the synced collection, the folder's canonical id,
the rule's name, all/any and its conditions, plus `from=browser` (read by AW-70). A rule whose folder is outside
the synced collection is `localOnly`; it has no move and its row says "Only in this browser: its folder isn't
synced." Signed out there is neither.

### Moving (`src/automation/browser-rules-pane.ts`)

*Add to your account* (row action) and *Add mine to the account* (in the AW-69 review, for a conflict) open that
editor in a new tab and send `known.automation.browser.moving`. The store marks `movingSince` once. The rule keeps
filing; its row reads *Moving* with "Waiting for your account's copy. Until it arrives, this browser keeps using
this one." Nothing is uploaded: the Owner previews and turns the rule on on the web (AU-02).

### Retiring (`retireMovedBrowserRules`)

After every bundle install, the account's rules in force here (projected to their folders here) are compared with
each moving rule. It is removed only when an enabled account rule is its duplicate: the same conditions after
normalization and the same folder in this browser. A notice tells an open Know-N page: ""arxiv.org → Papers" now
runs from your account, on every device." A draft (not in the bundle), a paused bundle, an account rule with
other conditions or another folder leaves it filing. Editing a moving rule clears the mark, because the edited
rule is no longer the one sent. A duplicate now counts even when no page could satisfy both rules
(`relateBrowserRule` checks it before the overlap signals).

Copy is in `en` and `zh_CN`.

## Limitations

- Retirement waits for the next bundle refresh: at most 5 minutes, or *Check now*.
- No real browser and server run of the round trip; the web half is AW-70's mocked editor test.
