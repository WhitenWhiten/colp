# AW-59 — web run-once preview and explicit start

Built on AW-45 (`5b45543`) on `main`. Contract `0.2.1-design`. Tests are driven by the AW-41 consumer
fixture, [fixtures/aw-41/handoff.json](fixtures/aw-41/handoff.json). The page sends a selection to
`POST /rules/:ruleId/run-once/preview` and starts it with `POST /rules/:ruleId/run-once`. It never lists,
counts, batches or restarts members itself: every count, the sample and `canStart` come from the
preview DTO.

## What shipped

### Run once — `/automations/rules/:ruleId/run-once`

A **Run once** button sits in the rule page header for every rule that isn't archived. The page uses the
rule editor's two-column layout: options on the left, and on the right the rule's sentence, the preview
and Start.

- **Selection options.**
  - **Folder.** Any folder in the rule's own collection; the server refuses any other collection. It
    starts at the collection's top level.
  - **Include its subfolders.** On by default.
  - **Also move bookmarks already in a folder.** Off by default, so a folder the owner chose counts as
    their choice.
  - **Agent tasks.** File only, or file and run its agent tasks. Shown only when the rule has tasks;
    otherwise `tasks: "none"` is sent.
- **Preview.** Sends the `RunOnceInput` built from the options, with `serverUuid` from the server manifest.
  Each attempt uses a new command id, so an identical body is still a new preview.
- **What the preview shows.**
  - How many bookmarks match the rule, how many of those stay where the owner put them, and how many
    can't be filed.
  - The server's sample, each bookmark with its decision: Matches, Stays put, Can't be filed, Doesn't
    match. Titles are rendered as text.
  - When the preview expires.
- **Start.** Enabled only for a preview that is current, not expired and has `canStart: true`, and it
  names the count ("Start on 47 bookmarks"). It sends exactly `{previewId, previewDigest}` with a
  Known-Command-Id, then opens the returned run. Start is the confirmation step: it is offered only
  beside the preview it starts. The hint says that moves happen right away and each can be undone from
  the run.
- **Changing a selection.** Any option change (folder, subfolders, foldered bookmarks, tasks) discards the
  preview at once and disables Start. A changed selection can only start after a new preview.
- **Expiry.** A timer re-renders when `expiresAt` passes. The preview then reads as expired, and Start is
  disabled.
- **Why Start is disabled.** When `canStart` is false, the page explains why from the preview's own
  counts:
  - over the `maxMembers` limit;
  - no matches;
  - bookmarks that can't be filed;
  - automations paused;
  - agent work unavailable.

  The server made the decision; the page only words it.
- **Refused starts.**
  - **Stale preview** (`automation_stale_input` or 412): the preview is discarded and the page asks for a
    new one.
  - **`automation_paused`, the daily capacity conflict and `payload_too_large`:** each gets a plain toast.
  - **Unknown outcome** (0, ≥500, 408, 429): the toast says Start can be pressed again. The preview stays,
    and the client replays the same command id, so the run can't start twice.

### Client

- `previewRunOnce(ruleId, input, attempt)` and `startRunOnce(ruleId, {previewId, previewDigest})`, using
  the same CSRF and command-id conventions as the other automation commands.
- The start command is keyed by preview id. It is kept after an unknown outcome and cleared after an
  answer.

`RunOnce.test.tsx` has 7 tests using the AW-41 fixture:

- The default whole-collection preview sends the fixture's `previewRequest` shape. The page shows the
  fixture's counts (3 matching, 2 staying) and its sample. Start then sends exactly the fixture's
  `startRequest`, once, and opens the returned run.
- Changing each option discards the preview and disables Start. The options are subfolders, foldered
  bookmarks, folder and tasks. The next preview carries the changed input with a fresh attempt id, and
  Start is never called.
- These previews don't start, and each explains why:
  - the fixture's `overLimitResponse` (1,000 = `maxMembers`);
  - one with bookmarks that can't be filed;
  - one with no matches;
  - the fixture's own preview, whose `expiresAt` has passed.
- A preview expiring while on the page disables Start.
- The fixture's `stale` 409 discards the preview, asks for a new one, and doesn't navigate.
- A 503 keeps the preview, and pressing Start again sends the same `startRequest`.
- The rule page links here, and an archived rule offers no preview.

A mutation check confirmed the tests catch regressions. With the preview reset removed from option
changes, or with the expiry check removed from Start, 3 tests failed. The source was restored afterwards.

A client test covers the preview and start URLs and bodies. It checks a distinct command per preview, and
the same command when a start is replayed after a 503.

## Limitations and contract gaps

- **Over-limit is inferred.** The preview has no `truncated` or reason field, so the page infers "over
  the limit" from `matched + blocked ≥ maxMembers`. A selection that is over the limit mostly because of
  non-matching bookmarks falls through to a general reason that mentions the limit. A server
  `startBlockers` list (for example `overLimit`, `paused` or `tasksUnavailable`) would remove the
  guesswork.
- **Rule's own collection only.** The rule is tied to its `scope.collectionId`. A rule without one gets a
  "no collection to run in" state instead of a form.
- **No resume.** The page does not continue an interrupted run, by design. A large run continues on the
  server, and its run page shows progress.
- **No real backend or hosted run.** Server behaviour comes from AW-41's integration evidence
  (`run-once.integration.test.ts`).
- No backend files were changed.
