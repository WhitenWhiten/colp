# AW-18 — complete authenticated browser bundles

> The final semantic/default corrections and overall acceptance are in [AW-66](aw-66.md); this record keeps the actual results when the task was committed.

Parent commit acfd5c1. The production GET bundle / POST bundle-acks reuse AW-17's device bearer/session authority.
The full snapshot contains a monotonic bundle revision, paused, settingsRevision, expiry, removedRuleIds and an authenticated response digest
covering all fields. M1 does not depend on target/policy; each active rule checks the current Owner, canonical bindings
and the device's current collection Sync range. At the time, anything unsupported/over-limit/unavailable rejected the whole snapshot, and pause returned an explicit disable.
(Superseded after review: selection is per collection — rules for collections the device does not sync are omitted, and a collection with an
intake rule the browser cannot evaluate exactly is delegated as a whole to server intake; over-limit still rejects the whole snapshot.)

Fixed a gap in the documented DTO: the original CompiledRule only had host/tag hints and could not express the existing finite DSL, priority,
scope and policy. contract-adjustments.json adds a required definition, generated into schema/TypeScript/OpenAPI
together; programId/parameters are only optimization hints and definition carries the complete semantics. No remote scripts or new language branches.
The browser-profile consumption requirements were updated; there was no published bundle endpoint yet, so no existing production API broke.

Actual verification: local shared package build/npm pack/install and runtime manifest rebuild passed, with no npm publish.
server typecheck, check:imports, ESLint, git diff --check and openapi:ci all passed.
- bundles + device-receipts integration: real PostgreSQL, 5 passed in total. The device fixture switched to the real
  authenticated bundle producer and no longer fakes a database snapshot directly.
- compile-bundle unit tests: 2 passed: generic startsWith/priority fidelity, and 1001 rules / 1 MiB over-limit are not truncated.
- shared-core automation tests: 6 files, 22 passed (including the existing browser-target bundle comparison).
Active/paused/expired/over-limit/unsupported hand-off cases are in fixtures/device-bundle-cases.json and the executable fixtures it links.
Chrome installation or native placement is neither implemented nor claimed. Test containers were reclaimed.
