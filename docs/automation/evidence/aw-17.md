# AW-17 — authenticated canonical device receipts

Parent commit b8426af. Adds POST /api/v1/automation-device/intake-receipts; it uses only the verified bearer
and requires Origin + Known-Sync-Session + Known-Command-Id. The design's DeviceBearer does not specify a separate device credential;
this implementation reuses the existing Sync session/device/replica generation binding to complete the proof, and the production OpenAPI is synced.
Authority is never taken from the request body's deviceId. Following the existing session→account→credential→replica→collection lock order it checks
the current Owner, credential revocation/security epoch, session and lease validity, scope and generation.

Receipts are strictly closed-validated and persisted as waitingForSync/accepted/review/rejected; a local receipt ID cannot be reused to
change evidence. Canonical facts and the Sync sequence receipt together prove the create and the optional placement move,
verifying the node, rule/binding/bundle pins, expiry/settings/activation fences, input and result digests and the current location.
Only the rule-declared classify.root is accepted; enrichment satisfaction and native browser IDs cannot be reported.
Source consumption re-joins waiting receipts before admission; accepted results do not create a run again.

Actual verification: server typecheck, check:imports, ESLint on new files, git diff --check and openapi:ci all passed.
Real PostgreSQL device-receipts.integration.test.ts passed three cases:
- Actually signed fixture tokens and the production session issuer, writing through the Sync Push application; receipt-first and create-first each create only one run;
- two real canonical operations create→move join and complete the existing admission without creating a second run;
- enrichment/native keys, mismatched canonical identity, old generations and wrong bearer/Origin are rejected.
The HTTP receipt route is verified through Fastify inject, with no claim of Chrome or production host behaviour. Sync writes go through the existing application entry,
not through the network Push endpoint; the device bundle in this task used a frozen database fixture, with production compilation following in AW-18.
Test containers were reclaimed.
