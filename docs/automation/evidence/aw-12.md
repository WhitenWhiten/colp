# AW-12 — web Automations page, rule editor, preview, needs attention, bookmark history

Baseline `b562baa` on `main`; contract `0.2.1-design` from `packages/server/openapi/fragments/automations.yaml`
(generated into `packages/web/src/generated/automations-v1.ts` by `npm --prefix packages/web run generate:api-types`;
re-running it produced a byte-identical file). The rule form is checked against the reviewed
`design/examples/m1-rule-create.json`. Every write goes through the backend DTOs; React holds no admission,
authorization or workflow logic.

## What shipped

- `/automations` is lazy-loaded. Its nav entry sits between Library and Agents in both TopNav and BottomNav,
  and appears only after `GET /me/automations/pause` answers. A 404, or a 403 `automation_mode_disabled`,
  hides the entry. The answer is cached per account in `localStorage`, but the server read still runs on
  every page load.
- While everything is paused, every page shows **Paused** in the nav: a flag in TopNav, and a dot plus
  visually-hidden text in BottomNav (AC-44).
- Library folder menus offer **Automate…** where automations are available. It opens
  `/automations/new?collectionId&folderId` with the destination already filled in.
- The home page lists:
  - **Needs attention** first: open incidents with their repair links and Check again / Dismiss, then runs in
    `review` grouped by the shared bookmark event. Two rules disagreeing read as one item naming both (AC-08).
  - Rules, each as one plain sentence with the folder's current name, its state, and per-rule Pause or
    "Preview and turn on".
  - **Pause all / Resume all** in the header. It sends If-Match with the pause revision and explains that
    bookmarks saved while paused are not processed later.
  - **Export rules**, which downloads `GET /me/automations/export`.
- The rule editor has three steps:
  - When: typed condition rows (site is, site ends with, title contains, has tag, path starts with), combined
    with All or Any.
  - Where: a collection and a folder picked by path. The binding uses the folder's
    `{serverUuid, collectionId, nodeId}`, never its label.
  - Then: shown only when `capabilities.taskTypes` is non-empty.

  Name, priority and the daily cap sit under *More options*. JSON lives under *Advanced*, which is closed by
  default. A stored rule the form cannot represent opens in Advanced instead of being paraphrased.
- Preview and Turn on:
  - Preview runs `POST /rules/preview` in `currentState` mode on the exact normalized configuration.
  - **Turn on** stays disabled until a preview of the configuration on screen exists. Any later edit marks the
    preview stale (AC-26). Turn on sends `activationPreviewId`.
  - If the server reports a stale preview, the editor drops it and asks for a new one.
  - Saving an enabled rule holds it until it is previewed and turned on again.
- The bookmark page has an **Automation** section listing runs for `{collectionId, nodeId}`, each named by its
  rule and its effects.
  - **Undo** appears only when the effect receipt says `undoAvailable`. It sends that effect's id, its digest
    and the run revision.
  - When Undo is not available, the receipt's `undoReason` is shown in plain words.
  - The section is absent where the server has no automations.
- Server sentences (run explanations, undo reasons, preview explanations) are mapped to plain copy when
  recognised and shown verbatim otherwise.
- Warnings and results use toasts. Inline status is used only for page or section state (paused note, stale
  preview, field errors).
- Styling:
  - New `styles/automations.css` in the `pages` layer, shared by `Automations.tsx` and `ResourceDetail.tsx`
    and registered in the CSS-layer contract and ARCHITECTURE.md.
  - The Know-N palette and tokens only, and the existing breakpoints.
  - Step markers use the self-hosted edition's ribbon index.
- The shared e2e passive mocks answer the pause read with 404, so every other mocked spec keeps its current
  chrome.

## Limitations and contract gaps

- **AC-41's two minutes is not measured with a person.** The scripted path takes five actions and no JSON
  (1.9 s automated). That shows the path exists; it is not a usability timing.
- **The full `npm run test` suite was not run.** Repo policy is to run only the affected suites; the ones run
  are listed above.
- **Preview groups decisions by explanation.** `currentState` preview decisions carry no bookmark title or
  node id, so the panel cannot list individual bookmarks.
- **"Needs a decision" comes from runs in `review`.** It groups them by `memberEventIds[0]` because
  the backend never emits a `ruleConflict` incident.
- **Disagreements don't link to their bookmark.** The Run DTO has no bookmark identity. AW-34 adds a run page
  link (`runHref`).
- **There is no list of bookmarks saved while paused or blocked.** The paused copy states that such bookmarks
  are not processed later.
- **The tag-feedback controls are not rendered.** The Owner job view exposes no accepted tag output, and the
  task requires the backend capability.
- **Export rules is on the Automations header.** The design pointed to the collection Export menu, but that menu
  is per collection while the export is per account.
- **Nav changes live in TopNav/BottomNav.** The task's file list names `Layout.tsx`, which needed no change.
- No backend files were changed.
