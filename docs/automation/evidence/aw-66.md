# AW-66 — independent M1 backend release gate

Task baseline d1065cf, BE-1 starting point f0c9a36. The task's actual file is
`packages/server/tests/integration/automation/m1-backend.integration.test.ts`, using the repository postgres
project's `.integration.test.ts` naming instead of the planned, undiscoverable `.test.ts`.

## Gate and corrections

Configuration, preview, enable, Product canonical create, the real Outbox repository/worker, the run/effect API and single-effect Undo go
through the actual Owner session/Origin/CSRF/command API. An injected exception before transaction commit verifies everything rolls back;
injecting a committed canonical/effect/cursor with a lost Outbox complete, a rebuilt worker replays and still produces a single effect.
After a real pg_dump/pg_restore the pause SQL of deploy/restore.sh runs, and a bookmark created and consumed afterwards cannot execute an effect.
The test uses a real database, test queue clock advancement and explicit fault injection, and does not claim a full deployment process or Chrome restart.
There are no M2 target/policy/subscription/usage tables; the M1 job count is zero.

The final check against chapters 11/14 corrected the initial AW-33 root-folder heuristic:
- Product create adds a compatible optional intakeDisposition=userDefault|userSelected, included in the command fingerprint.
  The default is unknown, which does not move even when the parent is root; only a proven default intent at the canonical root is admitted.
- In MCP only the existing default path that omits parentId is marked userDefault; an explicit root is userSelected.
- Ordinary Sync create does not infer default intent and keeps the current location. Canonical device placement receipts are verified to still join.
- The defaults required by the review docs are a 10-second receipt grace and a 7-day bundle expiry; these were restored and the offline pause window disclosed.
- The pre-save beforeFolder is advisory: Undo cannot be invented from it; placement is verified acceptable but Undo unavailable.
  classify.root satisfaction derives from the rule declaration and canonical evidence; the client's type list is not treated as a completion fact.
- The placement digest uses the shared registered contract placement.subtree.v1 and the intake stage identity.
- Added checks of the device's current durable scopes/replica write capability and a 2001-row precondition limit for history capture.

The separate automation Outbox added one queue row per operation, and the old canonical assertions were updated to verify both routes,
including per-route metadata. Identity reservation + enqueue were merged into one CTE; the large-sibling test keeps a
fixed round-trip limit (the original 75 plus at most 3 fixed capture/wake calls), with no relaxation that grows with node count.
(Superseded after review: capture is now gated by `KNOWN_FEATURE_AUTOMATION_CAPTURE`; with it off the canonical counts are
main's again, and the per-operation fact/wake assertions live in the automation fact-capture suite.)
