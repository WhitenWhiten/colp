# AW-33 — canonical server intake

> The final semantic/default corrections and overall acceptance are in [AW-66](aw-66.md); this record keeps the actual results when the task was committed.

Parent commit 6e10380. The production worker hooks up the durable admission→placement consumer. Each transaction handles at most 10 sources and
10 pending effects, with remaining work durably rescheduled through the existing continuation; compatible rules for the same source share one
canonical operation. A default 5-second Outbox grace lets device receipts join. Only Web/MCP/Sync creates whose
event-time parent is the collection/standard bookmark root are handled; import/restore/explicit folders are not moved automatically.
Creates from a Sync importer replica are marked import by the server; the origin is never guessed from client claims.

Before the effect the current Owner, live binding/subtree, source ancestry and resource revision/parent are re-checked.
The canonical move, automation causation, effect receipt, run completion and consumption cursor commit in one transaction.
Collection-version history is reused with cause=automation:<ruleId>; exceeding the 32 MiB serialized snapshot capacity
returns blocked without bypassing the history guarantee. A new manual move puts the run into review. Resuming from pause produces a separate durable resume
wake, so already-held pinned runs do not depend on the next bookmark event; sources from the paused period are still not replayed.

The runtime flag (then KNOWN_FEATURE_AUTOMATION_RUNTIME, now `KNOWN_FEATURE_AUTOMATION_ADMISSION`) defaults to false and is separate from the configuration flag;
both API and worker must enable it. Health/capabilities/readiness reflect the actually installed M1 composition and do not need Events, targets or M2 policy tables.
When Sync is not installed the production API only excludes device routes and can still run Web/MCP M1 on its own.

Actual verification: typecheck, check:imports, ESLint, migration ordering and git diff --check passed.
- server-intake.integration.test.ts: real PostgreSQL, 3 passed (Web/MCP, explicit folder/import, duplicate delivery,
  history cause/causation, later manual move, hold/resume/skip fences).
- admission + health integration: 11 regression cases passed.
- composition unit: 4 passed, including runtime gating and readiness independent of Sync.
No model, Events or browser-native calls. The database container is reclaimed by the wrapper.
