# AW-33 — canonical server intake

父提交 6e10380。生产 worker 接入 durable admission→placement consumer。每事务最多 10 个来源、
10 个 pending effects，剩余工作用既有 continuation 持久重调度；相同来源的兼容规则共享一次
canonical operation。默认 5 秒 Outbox grace 给设备 receipt 汇合。只处理 Web/MCP/Sync create
且 event-time parent 是 collection/标准书签根目录；import/restore/显式目录不自动移动。
Sync importer replica 的 create 被服务端标记 import；不从客户端声明猜测来源。

效果前重新检查当前 Owner、live binding/subtree、source ancestry、resource revision/parent。
canonical move、automation causation、effect receipt、run completion 与消费 cursor 同事务提交。
沿用 collection-version history，cause=automation:<ruleId>；现有 2000-member snapshot capacity
超限返回 blocked，不绕过历史保证。新手动移动让 run 进入 review。暂停恢复产生独立 durable resume
wake，因此已持有的 pinned run 不依赖下一次书签事件；暂停期间来源仍不会补跑。

运行开关 KNOWN_FEATURE_AUTOMATION_RUNTIME 默认 false，和配置开关分开；API/worker 都要启用。
健康/能力/readiness 反映实际安装的 M1 composition，不需要 Events、目标或 M2 policy tables。
生产 API 在 Sync 未安装时只排除 device routes，仍可独立运行 Web/MCP M1。
