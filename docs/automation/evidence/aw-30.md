# AW-30 — conditional MCP catalogs

基线 `5f9fbd2`。按冻结 catalog 的七个 manager、八个 worker（共十五个）工具生成
闭合 input/output schemas；叠加已有 contract-adjustments 与 UUIDv4 command 约定。
`check:automation-tools` 纳入 OpenAPI Automation 检查，防止描述符与校验器漂移。

list、get、直接 call 共用当前 profile/catalog/scopes/pairing 判定。未配对 opted-in worker
只见 pair；配对后只见 worker tools；standard/manager 必须显式组合并拥有实际 scope。
worker-only 不暴露普通 nodes/resources。普通未 opt-in agent 保持现有目录。
目录无全局缓存，身份含 principal/scopes/profile revision/target generations；动态 strict
目录 private TTL=0，compat 原有 no-store 与 listChanged=false 保持一致。

target access 从当前数据库读取并再次验证凭据。strict/compat 只从现有 branded OAuth
结果传递 Automation 所需的 token-free expiry/digest/epochs；无原始 bearer，也不扩散到
普通 agent residual。可选字段缺失时省略，避免 undefined 进入 JSON contract。

实际验证：
- xvfb PostgreSQL `tool-catalog.integration.test.ts`：3 项通过。真实 JWT、真实 child-key
  exchange、Owner API、单次 pairing、当前 OAuth/machine 撤权；验证组合目录的逐 scope
  过滤、直接调用拒绝、闭合参数校验、cache identity 改变、worker resource 隔离。
- 现有 application-catalog-facade、compat-admission-oauth、list-wire：3 文件 15 项通过。
  初轮回归发现普通 OAuth residual 多出缺省 undefined 字段导致 wire 拒绝，已按上述方式
  修复并重跑通过。组合测试初轮 stale ETag 被正确拒绝，改为读取更新后的 target ETag。
- typecheck、imports、generator drift、修改文件 ESLint 通过。

目录 fixture 的业务 dispatcher 明确返回 unsupported，不伪造 claim/result 成功。
生产挂载与十五项工具的真实应用调用在依赖 AW-23/24 的 AW-31 统一接入；本项证明目录
与当前权限边界，不把目录 fixture 当作业务闭环。没有 Events 生产订阅或模型调用。
临时 PostgreSQL 由测试 wrapper 回收，没有常驻服务。
