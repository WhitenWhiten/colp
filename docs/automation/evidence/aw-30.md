# AW-30 — conditional MCP catalogs

Baseline `5f9fbd2`. Closed input/output schemas are generated for the frozen catalog's seven manager and eight worker (fifteen in total) tools,
layered with the existing contract-adjustments and the UUIDv4 command convention.
`check:automation-tools` is part of the OpenAPI Automation checks, preventing drift between descriptors and validators.

list, get and direct call share the current profile/catalog/scopes/pairing decision. An unpaired opted-in worker
only sees pair; after pairing it only sees worker tools; standard/manager must be combined explicitly and hold the actual scope.
Worker-only exposes no ordinary nodes/resources. An ordinary agent that has not opted in keeps the existing catalog.
The catalog has no global cache; its identity includes principal/scopes/profile revision/target generations; the dynamic strict
catalog has private TTL=0, consistent with compat's existing no-store and listChanged=false.

Target access reads from the current database and re-verifies the credential. strict/compat only pass the token-free expiry/digest/epochs
Automation needs from the existing branded OAuth result; no raw bearer, and nothing spreads into the
ordinary agent residual. Missing optional fields are omitted so undefined never enters the JSON contract.

Actual verification:
- xvfb PostgreSQL `tool-catalog.integration.test.ts`: 3 passed. Real JWT, real child-key
  exchange, Owner API, single pairing, current OAuth/machine revocation; verifies per-scope filtering of combined catalogs,
  direct-call rejection, closed parameter validation, cache identity changes and worker resource isolation.
- Existing application-catalog-facade, compat-admission-oauth, list-wire: 3 files, 15 passed.
  The first regression found the ordinary OAuth residual gained a default undefined field that the wire rejected; fixed as above
  and re-run successfully. The combined test's first run correctly rejected a stale ETag and now reads the updated target ETag.
- typecheck, imports, generator drift and ESLint on changed files passed.

The catalog fixture's business dispatcher explicitly returns unsupported and does not fake claim/result success.
Production mounting and real application calls of the fifteen tools are wired together in AW-31, which depends on AW-23/24; this item proves the catalog
and the current permission boundary and does not treat the catalog fixture as the business loop. No production Events subscriptions or model calls.
Temporary PostgreSQL is reclaimed by the test wrapper; no resident service.
