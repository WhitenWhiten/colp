# AW-58 — persisted run outputs and read watermarks

Accepted digest/review text persists atomically with its typed result, linked to
result/job/run/target. It creates no canonical mutation plan or fake effect receipt.
Compatible result reuse gives the receiving run a separate output/unread identity
while retaining original evidence and checking owner/input/contract/authority pins.

Owner output list and mark-read APIs reuse session/CSRF/command receipts, current
collection ownership and source availability checks. A missing source produces a
clear unavailable response without retained private output text. DTO text is untrusted
plain text (JSON, never executable markup); consumers must use escaped text bindings.
Persisted source evidence is not sanitized into a different claimed model response.

Output order is `(createdAt,id)` with database serialization and a microsecond floor
per run, preventing a later arrival from falling behind a read watermark even if the
wall clock repeats or moves backward. Cursor and watermark preserve database timestamp
precision. `throughOutputId` is scoped to the run, watermark only advances, and current
Run If-Match protects mutation races. Run.outputCount/unread derives from durable rows.
No cache or webhook replay supplies digest state. Output history stays under AW-44's
conservative retention policy; immutable rows and compact read state survive restart.

text, and prevents output updates. Backend OpenAPI/routes are regenerated. Consumer
[page/read fixtures](fixtures/aw-58/handoff.json) are synthetic and use no live secrets.
