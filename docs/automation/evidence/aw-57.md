# AW-57 — exact count-batch aggregation

Count admission locks immutable revision/epoch/partition state, records distinct
membership and removes exactly N ordered members per batch. Membership, immutable
run snapshot, target/task pins, ready wake and remainder commit with the source cursor.
Source receipts and membership identities survive replay. Partitions also bind binding
and policy revisions, so configuration changes cannot merge incompatible inputs.
Node and normalized-URL distinctness are supported; normalized URLs use WHATWG URL
serialization, retain query, remove fragment and normalize host/default port.

The installed count profile supports single-target run-level digest/review DAGs and
no per-bookmark placement. `intake.completed` is derived from committed canonical
intake move facts; original creation and same-stage reentry are not double-counted.
Pause skips the paused source interval while preserving a same-revision aggregate
epoch/remainder. Semantic revisions retain old evidence and start separate counters.

Jobs pin all member inputs, revisions, note sets and predecessor results (4 MiB total
input cap). Existing authenticated input pagination reads that exact list. A member
change/deletion causes stale/review, never a replacement. Daily budgets/claims and
current authority remain in the existing worker path. Source members and unfinished
remainders remain protected by AW-44 retention policy. Migration 202610302100 follows
AW-41's 202610302000; immutable membership updates are database guarded.
