# AW-28 — verified callbacks and encrypted signing keys

The production Events composition now installs a verifier when explicitly enabled.
`AUTOMATION_WEBHOOK_MASTER_KEY` must be canonical base64 encoding of 32 random bytes;
configuration fails closed without it. Preserve this key in private backup management.
Secrets use domain-separated AES-256-GCM with subscription ID as authenticated data.
Owner export does not include subscription rows, URLs or ciphertext.

Challenges and occurrence transport reuse hardened HTTPS egress: all DNS answers
must be public, connections pin the validated address, TLS retains the hostname,
redirects are never followed, deadline is 10 seconds and response limit is 8 KiB.
Callbacks receive only generated signature/content headers, no request credentials.
Verification requires HTTP 200 and constant-time comparison of a fresh random echo.
Every attempt signs exact stored bytes with a current Unix timestamp. A previous
secret signs only within the persisted five-minute rotation window.

Executed server typecheck and focused `tests/unit/automation/webhook.test.ts`:
4 passed. Tests independently calculate HMAC, test old/new signature windows,
ciphertext substitution and wrong-key rejection, decoded secret bounds, pinned
address/hostname, absent credentials, private mixed DNS, redirect refusal, bad echo,
204 and oversized response. An initial assertion expected `redirect:error` at the
connector; corrected to the hardened adapter's actual `manual` single-hop contract.
No public callback or real dot was invoked. Lifecycle/database fences are AW-27;
end-to-end protocol fixtures and hosted-only gaps are recorded by AW-46.
