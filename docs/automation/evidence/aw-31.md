# AW-31 — authenticated worker HTTP and MCP orchestration

基线 `3bb4fd1`，contract `0.2.1-design`。接续 AW-31 后停止；未开展 AW-32 或后续任务。
按 ADR-BE1 和冻结 catalog 挂载七个 manager、八个 worker（共十五个）工具。
HTTP 与 MCP 复用配置、配对、ready queue、输入、lease 和 typed result 应用服务；
list/get/call 继续使用 AW-30 的当前 profile、scope、credential 和 pairing 判定。

生产 API 在 Automation configuration/runtime 与 MCP Write 组合可用时挂载 worker 服务，
outbox worker 同时启用任务 admission/scheduling。确定性 intake 先执行，不消耗 optional
预算；每个任务首次 ready 时固定 allowlisted inputs、revision、声明的已接受前序结果和
input digest。迁移 `202610301400_automation_worker_input_pins.ts` 在数据库保护这些 pins。
只串行推进同一 source 上的任务，不改写声明的 DAG；canonical 后续 revision 来自 effect
receipt，手动修改使旧输入失效。每个 ready job 都有 ledger deliveryHandle，无需 Events。

claim token 不进入持久 command receipt；claim 重放要求 reconcile，不重新发放 secret。
heartbeat 重放重新检查当前 lease；submit 通过固定 proposal/plan/command identity 恢复。
过期 lease 转为 uncertain，Owner 只能在无 durable proposal、输入未变且 pinned maxCalls
有余量时显式 retry；保留 unknown-cost 计数并增加 claim generation。Owner HTTP decision
要求当前 ETag 和精确 proposal digest，复用现有 Plan/Approval ledger。canonical commit
之前再检查当前 worker、target、input 和 subtree authority。

Job 增加 Owner 审批需要的 resultId/proposalDigest/planId 和 explanation；TaskInput 增加
声明 DAG 前序结果。调整登记在 `contract-adjustments.json`，同步 Node schema/types、server
vendor、OpenAPI 和 MCP descriptors。输入缺少 readableText/metadata/folderDefinitions
能力时明确 blocked，不隐式抓取或调用模型。`AUTOMATION_SERVER_DAILY_RUN_CAP` 默认 1000。
