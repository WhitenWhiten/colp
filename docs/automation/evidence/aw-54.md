# AW-54 — extension: server run status, apart from placement

Built on AW-21 (`81abe4c`) on `main`. Contract `0.2.1-design`, profile `browser-bounded-v1`, shared core
`@know-n/colp` 0.2.0. The DTOs are `RulePage` and `RunPage`, validated with the standalone validators
generated from that core. Stories AU-22 and AU-23.

## What shipped

### Reading the server's own status (`src/automation/server-status.ts`)

- **What is read.** `GET /api/v1/me/automations/rules?limit=100` and
  `GET /api/v1/me/automations/runs?limit=20`, newest first as the server orders them.
- **How it is read.** With the browser's web sign-in: `credentials: 'include'`, `redirect: 'error'`,
  no-store, and only an `Accept` header. The Sync bearer is never sent, so the server's
  mixed-carrier refusal never triggers. The worker already reads `/api/v1/me` the same way.
- **Validation.** Both answers are checked against the contract (`RulePage`, `RunPage`). The
  `RulePage` validator is new in `scripts/generate-automation-validators.mjs`. An answer outside the
  contract is refused as `invalid`, never partly shown.
- **The kept copy.** It lives in the automation IndexedDB store (`known.automation.server.v1`, owner
  scoped) and holds only what pages show:
  - per rule: id, name, effective state, and the server's usage counts and cost wording;
  - per run: id, rule id, kind, status, hold, unread, output count, explanation and times.

  It keeps no member event ids, job ids or effects.
- **A failed read keeps the last copy.** It records why: offline, signed out, rate limited, server,
  invalid. A 404 marks the server as without automations, and the section is hidden.
- **When it is read.** Within the existing worker pass (`refreshAutomation`): the five-minute
  automation alarm, opening Options › Automations, and "Check now". At most once a minute, backing
  off to 15 minutes while the server fails. The read does not depend on Sync's authority, so the
  server's status still arrives when the bundle refresh can't.

### One place for the words (`src/automation/status-ui.ts`)

- **Run states use the web's vocabulary.** Waiting, Running, Needs a decision, Done, Partly done,
  Blocked, Cancelled, Failed. An explicit hold shows as On hold. Tone appears only for problems
  (one badge per row, as the extension's kit requires).
- **Explanations.** The server's fixed sentences become the web's owner-facing sentences, translated
  in `zh_CN` like the rest of the extension. Unknown text is shown as sent.
- **Rule state.** A rule that isn't simply on shows "On, with problems", Blocked or Paused. The
  server's own counts appear as they are: jobs waiting for an agent, held by a limit, needing your
  approval. So does its cost wording ("Billed by your agent"). Nothing is summed, inferred or
  re-derived, and no workflow state machine exists in the extension.
- **Placement state.** The receipt badges (moved here from the pane) stay the placement's own.
- **Freshness.** "Updated 2 minutes ago.", or "Couldn’t reach your server. Showing what it said
  3 hours ago.", or the sign-in, invalid and checking variants.

### Options › Automations

- **Placements and runs are two groups.**
  - **Recent placements** is this browser's receipts: what it filed, and whether the server
    confirmed the placement.
  - **On your server** is the server's runs, each opening its page on the web
    (`<server>/automations/runs/<id>`).

  A confirmed placement carries no badge, even when a run on that bookmark failed. A run never reads
  as done because the bookmark was filed.
- **Rules.** The Rules list adds each rule's server state and waiting work. Rules that only work on
  the server, such as a digest, are listed with "Works on your server; nothing to file here."
- **Without a web sign-in** in this browser, the section asks for one ("Open Automations").
- **Without server automations,** the section is hidden. Signed out of the extension, nothing
  changes.

No local claim is made about model spending, delivery or approval. Those appear only as the server's
counts and words.

## Limitations

- **No live server was used.** The fixtures pass the shared contract validators, and the server's
  route reads the same DTOs. The cookie read is the one the worker already uses for `/api/v1/me`;
  whether a given self-hosted cookie reaches it depends on the browser's web sign-in for that origin.
  Without one, the page says so.
- **What is read.** Only the first page of rules (100) and the 20 newest runs. The section shows 8
  and links to the web for the rest.
- **Server text in English.** The cost wording and any unmapped explanation are shown as the server
  sends them, in English.
- **Not in the popup.** The per-bookmark history in the popup (AU-13, compact list under the folder
  pill) is not part of this task.
- **Found while reading AU-33: disconnect cleanup.** "Disconnect server" does not yet remove the
  local automation store (bundle, receipts, intents, server status). That story belongs to
  AW-01/09/44/63/66, not this list, and is left for them.
- No backend or web files were changed.
