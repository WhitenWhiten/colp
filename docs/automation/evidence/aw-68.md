# AW-68 — extension: write and manage browser rules in Options › Automations

Built on AW-67 (`5998368e`) on `main`. Design [01 §7.5](../design/01-architecture.md#75-browser-rules-adr-a24-au-34),
story AU-34; acceptance AC-69, now run in a real browser.

## What shipped

### The page (`src/automation/options-pane.ts`, `src/automation/browser-rules-pane.ts`)

The pane keeps the anatomy the account's rules already use (page head, one status card, one bordered list
with hairline rows, recent activity). This browser's own rules are one more group in it.

- **Signed out.** The page leads with *Rules in this browser*. Under it, one quiet card says what an account
  adds ("Your account's rules … They work on every device, and run before this browser's") with *Sign in*.
  There is no status card and no web link. Before this packet the whole page was "Sign in to use automations".
- **Signed in.** The status card and *Your account's rules* (renamed from *Rules*, with *New rule on the web*
  in its head) come first; *Rules in this browser* follows, worded as the layer below.
- **Rows.** Each rule reads like the web's sentence ("From arxiv.org → Papers"); the sentence helper moved to
  `status-ui.ts` (`ruleConditions`) so both lists share it. A row has a switch, *Edit* and *Delete* (on hover),
  and a badge only when something needs attention: *Off*, or *Folder missing* when its folder was deleted.
  Clicking the row opens it. On narrow screens the switch keeps the end of the first line and the badge and
  actions go under the text.
- **New rule** in the page head now opens the browser editor, signed in or not. Account rules are still made
  on the web, from their own group.
- **Recent activity › This browser** lists pages browser rules filed (`state: 'filed'`, no badge) together with
  the account's placements. With only browser placements its lede reads "Filed in this browser by your
  rules." instead of promising a server confirmation.

### The editor

One dialog, in the order the web uses: *When a page* (condition rows: site is, site ends with, title
contains, link path starts with; *Add condition*; *Match all/any of these* once there are two), *Save it in*
(the folder pill over this browser's folders, subscription folders left out), then *Name (optional)*.

- The folder pill starts empty ("Choose destination") for a new rule rather than defaulting to the
  Bookmarks bar (`startEmpty` on `createFolderPicker`; other callers are unchanged).
- An unnamed rule gets the web's name: "arxiv.org → Papers" (a pasted link stands for its site).
- No condition and no folder are said at once. Everything else is checked by the worker, and its problems
  land on the row or field they are about ("Use a site name, such as arxiv.org.").
- Without bookmark access the dialog shows *Allow bookmark access* in place of the folder list.
- Results are toasts (*Saved "…"*, *Deleted "…"*); deleting asks first and says filed pages stay put.

### Worker (`src/sw/automation.ts`, `src/sw/automation-browser.ts`)

`AutomationStateView` gains `browserRules` (name, on/off, sentence, the editor's draft, the folder's title and
path, or `folderMissing`) for signed-in and signed-out pages alike, and its placements include browser
placements, newest first. Copy is in `en` and `zh_CN`.

## Limitations

- The account's pause stays on the web; browser rules have only their own switches.
- Star-button creations stay account-only (design 01 §7.5).
