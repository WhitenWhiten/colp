# AW-25 — existing Approvals, plan history and conservative Undo

Baseline `f5c2d37`; design `0.2.1-design`. The Owner proposal decision adapter points to the existing
Plan/Approval API and checks the job ETag and proposal digest exactly, without creating a second approval state.
AW-24 actually verified approve -> commit through the existing Approvals. The Owner decision transport is mounted in AW-31.

Run history links the same plan, operation and version; EffectReceiptView gains a compatible optional versionId,
synced from one source into the shared schema/types, Product OpenAPI, the actual local pack, the vendored tarball and both locks.
Read-only recovery only looks up the consumed plan/canonical operation and neither approves nor executes new effects. If completion was lost after
commit, Owner history can still recover the receipt even when the run was cancelled; it stays cancelled, the first new receipt
advances the Run ETag, and repeated reads do not. The worker's current permission check still applies to all new effects.

The only undoable plan unit is a single move with a proven original location, reusing AW-51's verified canonical
compensating move, allowed only when the current Owner/resource/content/original-folder fences all hold. It never overlays a whole
collection version onto newer changes. The existing tree snapshot only covers structure, title and URL, not tags/notes; those two and
combined/non-isolatable plans are explicitly unavailable. No new field-selective restore capability is claimed here.
AW-52's six-status hand-off is in fixtures/aw-25/statuses.json, explicitly a contract fixture, not online evidence.
