# AW-25 — existing Approvals, plan history and conservative Undo

基线 `f5c2d37`；设计 `0.2.1-design`。Owner proposal decision adapter 指向现有
Plan/Approval API，精确校验 job ETag 与 proposal digest，不建立另一份审批状态。
AW-24 已实际验证现有 Approvals 的 approve -> commit。Owner decision transport 在 AW-31 挂载。

Run history 链接同一 plan、operation、version；EffectReceiptView 增加兼容的可选 versionId，
并同源同步 shared schema/types、Product OpenAPI、实际本地 pack、vendored tar 和两个 lock。
只读恢复只查 consumed plan/canonical operation，不审批或执行新效果。commit 后 completion
丢失，即使 run 已取消，Owner history 仍能恢复 receipt；保留 cancelled，首次新增 receipt
推进 Run ETag，重复读取不推进。worker 当前权限检查仍用于所有新效果。

唯一可 Undo 的 plan 单元是一个已证明原位置的 move，复用 AW-51 已验证的 canonical
补偿 move，当前 Owner/resource/content/原目录 fences 均成立才允许。不会把整个集合版本
覆盖到新改动上。既有 tree snapshot 仅覆盖结构、title、URL，不覆盖 tags/note；这两类及
组合/不可隔离 plan 明确 unavailable。这里没有声称新 field-selective restore 能力。
AW-52 的六种状态 handoff 在 fixtures/aw-25/statuses.json，明确是契约 fixture，非线上证据。
