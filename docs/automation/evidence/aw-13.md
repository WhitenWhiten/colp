# AW-13 — canonical event-time facts

Baseline f0c9a36; the worktree was renamed from automation-be1 to automation, branch feat/automation.
Design inputs are design/tasks.json AW-13 and 09-data-model §2 (BE-2).

The canonical order gains a required facts port between audit and outbox. The production adapter saves the before/after
URL/title/tags/parent/ancestor identity during the planning phase while holding the collection lock; capture only consumes the plan and allocation result
and does not re-read the node. The ancestor limit is 128; exceeding it or a broken chain explicitly sets ancestryComplete=false without faking complete facts.
The private table stores no description, readable content, extensions or credentials; generic events gain no fact payload.
Web, MCP and Sync entries carry server-side provenance; explicit import/restore/automation contexts are bound by internal callers
and are not derived from user resource DTOs. The repository currently has no separate Product import endpoint; import callers can bind
automationOrigin='import' through the canonical unit of work. Unknown internal writes stay system and are never guessed to be user creations.
The facts' source_event_id uses the canonical domain event identity allocated in the same transaction.
(After review, capture runs only with `KNOWN_FEATURE_AUTOMATION_CAPTURE=true`.)
